# Exception Handling

## Required Response

1. Stop the affected action safely.
2. Preserve the current record and prior work.
3. Record what failed, when it failed, and the available evidence.
4. Prevent duplicate sends, records, or stage changes.
5. Route the exception for human review when required.
6. Resume only after the blocker is resolved and the next action is approved.

## Initial Exception Categories

- Missing or contradictory prospect data
- Duplicate prospect or customer record
- Missing human approval
- Invalid or suppressed destination
- Integration unavailable
- Send accepted but delivery unconfirmed
- Journey-stage conflict
- Video, content, or link not approved

Detailed retry and escalation policies will be defined with each approved automation.
